# Professional Self Assessment

Completing the Computer Science program and developing my ePortfolio has given me the opportunity to look back at how much my skills have developed since I began the program. Throughout my coursework, I worked with several areas of computer science, including software development, data structures and algorithms, databases, testing, security, and application design. Working across these different subjects helped me become more comfortable taking a problem, breaking it into smaller parts, and developing a solution that can be tested and improved over time. It also showed me that one of my strengths is being willing to continue working through a problem when the first solution does not work as expected.
Developing the ePortfolio helped me see my progress more clearly because I returned to projects that I had completed earlier in the program and evaluated them with the knowledge I have now. Instead of only looking at whether the original programs worked, I began thinking more about how the code was organized, how data moved through an application, how users interacted with it, and how the design could be improved. Revisiting my previous work also helped me recognize areas where I have become more confident, including debugging, reading existing code, working with multiple parts of an application, and making changes without breaking functionality that already works.
The program has also helped shape the way I think about my professional goals. I have learned that I enjoy building practical software and seeing how individual pieces of a program come together to create a complete application. I also value writing software that is understandable, useful, and reliable rather than only focusing on getting a program to run. As I prepare to enter the software development field, I feel better prepared to continue learning new technologies, work through unfamiliar problems, communicate my decisions, and improve my work through testing and feedback.
Throughout the program, I also learned that software development is not only about writing code. It requires communicating ideas clearly and creating work that other people can understand and use. My coursework involving Agile development helped me see how collaboration can affect the development process. Activities involving planning poker, group discussion, estimation, and organizing requirements showed me that different people can look at the same problem in different ways. Discussing those differences can lead to better estimates and better decisions than working without input from others.
These experiences also helped me understand the importance of communicating with stakeholders. Many course projects were based on requirements from clients or organizations, which meant I had to interpret written requirements and turn them into working software. This required more than simply adding features. I had to understand what the user needed, decide how those needs should be represented in the application, and test whether the final result behaved as expected. I learned that a technically correct solution is not very useful if it does not actually meet the needs of the person or organization it was designed for.
My coursework also helped me build a stronger understanding of data structures and algorithms. Earlier in the program, I mainly thought about whether a program produced the correct result. As I progressed, I became more aware that the way data is stored and processed can have a major effect on how understandable and efficient a program is. I worked with structures such as lists, maps, and other collections, and I learned how choosing an appropriate structure can make operations such as searching, sorting, and retrieving information easier to manage.
I also gained more experience thinking through the individual steps that an algorithm follows instead of only focusing on the final output. This became especially important when working with search and sorting operations, where I had to consider how records were stored, how values were compared, and how results should be returned to the user. These experiences helped me become more comfortable breaking larger tasks into smaller logical steps and checking whether each part was working correctly. I now understand that there can be several valid ways to solve the same problem and that part of software development is choosing an approach that fits the goals and size of the application.
Software engineering is another area where I have seen significant growth. I learned that developing a complete application involves much more than writing individual functions that work on their own. A larger program needs clear organization, readable code, testing, error handling, and a design that can be changed when requirements develop over time. For example, in CS 465, while working on an Angular project for a Travlr application, I had to troubleshoot how style files were configured and loaded by the project. Resolving problems with file paths and application configuration helped me understand how many different pieces of a software project can depend on each other.
I also gained experience working with software outside of a traditional desktop application. In CS 350, I worked with a Raspberry Pi environment and connected to the system remotely while working with embedded software. That experience exposed me to another type of computing environment and showed me that the same problem solving skills apply even when the hardware, operating environment, and development tools are different. Experiences like this made me more comfortable approaching unfamiliar systems and learning how their components fit together.
Testing and debugging also became a much larger part of how I approach software development. I learned to make changes in smaller steps, test the results, and use problems I found during testing to guide the next improvement. Instead of changing many parts of a program at once, I became more comfortable isolating problems and confirming that each change behaved correctly before continuing. This approach has helped me become more patient when debugging and has made it easier to understand why a problem occurred instead of only trying different changes until something works.
My database coursework gave me experience with storing, retrieving, and processing information through a database instead of keeping all data directly inside an application. I worked with database queries, CRUD operations, and connecting application code to persistent data. This helped me understand the value of separating the database layer from the user interface and other application logic. It also helped me see how the design of the data layer can affect the rest of an application, especially when users need to search, filter, update, or display large collections of records.
Security is another area that changed the way I think about software development. Earlier in the program, I was more focused on whether a program worked correctly. As I gained more experience, I learned that a program also needs to protect its data, handle unexpected input safely, and avoid creating unnecessary opportunities for misuse. Security should be considered while an application is being designed instead of only after the rest of the application has been completed.
One security exercise from CS 405 that helped reinforce this involved using C++ and regular expressions to recognize patterns that could indicate SQL injection attempts. Working through input normalization, suspicious query patterns, and preventing unsafe queries from continuing helped me better understand why user input cannot automatically be trusted. It also showed me how small programming decisions can have security consequences. My coursework made me more aware of practices such as validating input, protecting sensitive information, limiting unnecessary access, and avoiding the exposure of credentials or private data.
This security mindset also influenced the way I reviewed older projects during the capstone. I paid more attention to database connection information, user input, error handling, and the amount of access different parts of an application should have. Even when security was not the main focus of an enhancement, I became more aware of design choices that could create problems in a larger or real world application. I believe this awareness will be important as I move into professional software development because creating useful software also requires considering how the application and its data can be protected.
The artifacts in my ePortfolio work together to show several areas of my growth throughout the Computer Science program. My first two enhancements use a project from CS 320 that manages contacts, tasks, and appointments. The software design and engineering enhancement focused on bringing the separate parts of that project together into a more complete application. The algorithms and data structures enhancement built on that work by adding search and sorting features that made better use of the collections already used by the program. These enhancements show how I can review an existing project, identify areas for improvement, and expand its functionality without starting over from the beginning.
My third enhancement uses the Animal Shelter Dashboard and MongoDB project from CS 340. This artifact demonstrates a different area of my experience by focusing on database integration and the connection between stored data, application logic, and an interactive user interface. Improving the dashboard so that MongoDB became the main source of data gave me an opportunity to apply database queries, CRUD operations, filtering, visualization, and usability improvements in one project.
Together, these artifacts represent the progress I have made in software design, algorithms, data structures, databases, testing, debugging, security, and application development. They also show how my approach has changed throughout the program. I have become more comfortable reviewing existing code, planning improvements, testing changes, and thinking about how different parts of a system work together. The code review, enhanced artifacts, and narratives that follow provide examples of these skills and demonstrate how I have developed from completing individual programming assignments into thinking more carefully about the design and quality of a complete software solution.
Completing this ePortfolio has helped me recognize both the skills I have developed and the areas where I want to continue growing. I know that entering the computer science field will require continued learning, but the experience I gained throughout this program has given me a stronger foundation for taking on new technologies and unfamiliar problems. I feel better prepared to approach software development with patience, attention to detail, and a willingness to improve my work through testing, feedback, and continued practice.
